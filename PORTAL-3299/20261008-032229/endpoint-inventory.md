# PORTAL-3299 endpoint contract inventory

Read-only source audit of `sbhushan/PORTAL-3299_encryption_key_dispatch_refactor`, HEAD `3fdd4f6e1`, against merge-base of `feature/PM-1957-EKEYS_MVI_3`. No source files, fixtures, or endpoints changed by this audit. The source audit itself does not establish test results.

All paths below are exposed at root and under `/v1`. All nine encryption routes require tenant authentication, account rate limiting, and feature flag `encryption_keys_experience`. Absent permission/feature/license returns 403; malformed UUID/query/body normally returns 422. Write acceptance is 202 and does not establish appliance completion. Minimum appliance version is 10.6; reachable means heartbeat age strictly less than ten minutes. Readiness precedence is missing/stub appliance → wrong family → version → offline → matching in-flight task.

## Version and task behavior that needs explicit regression coverage

- Escrow/delete previously rejected `None`, `master`, and UNKNOWN build values through strict `allow_*=False`; refactor uses common policy that allows these values. Valid below-10.6 and malformed values still reject. Boundary-test `10.5`, `10.6`, newer, malformed, `None`, `master`, and the actual UNKNOWN constant. Classic family includes null/`Edge`; `Strider` is rejected before version/offline classification.
- Ordinary accepted writes keep `TaskCreatedDto = {id,state,status_url}`. Bulk escrow now has `items:[{key_id,task:{task_id,action,executor_id,state,error},rejection:null}]`, or a rejection with task null. The old `task.id`/`task.status_url` are absent. `error` exists iff failed and contains only curated `message` + `detected_at`, never raw step errors.
- Escrow uses `raise_on_send_failure=False, ack_on_send_failure=True`; all six encryption dispatch operations acknowledge a newly persisted dispatch failure. A failed bulk snapshot is still returned although its task is already acknowledged and omitted from subsequent active-task resource lists.
- New `TaskRepo.fail_dispatch` locks parent first, changes only the selected pending/in-progress step plus parent atomically, preserves sibling steps, terminal parent outcomes and acknowledgement, and builds return DTO before commit. Missing/settled named step leaves parent unchanged. Stepless legacy task still fails parent alone. Exercise send/serialization/message-persistence failures, commit/step/parent failures, concurrent terminal event winning in either order, cross-tenant IDs, no query after commit, and repeated failure not acknowledging an earlier unseen background failure.
- If failure persistence raises in non-raising bulk mode, response contains original potentially stale in-progress snapshot; it does not prove dispatch succeeded. Strict callers propagate persistence errors. Task creation errors and cancellation always propagate. Convenience helper rejects multi-step actions before task creation.
- Active resource tasks are in-progress or failed/unacknowledged. Non-stub status: in-progress wins `pending`, otherwise failed, otherwise synced. Stub: failure-only → failed; otherwise creating. Acknowledged/completed tasks do not affect status. Verify `/tasks/{id}`, list views, and acknowledgement after controlled task transitions.

## Appliance command contract

All six encryption writes use FIFO Classic wire commands; `trace_id` is task ID. Portal forwards encrypted passphrase unchanged and strips it from persisted message data.

| API write | Wire command | Payload fields | Task resource / action / step |
|---|---|---|---|
| bulk escrow | `escrow_encryption_key` | `fingerprint` | `encryption_key` / `escrow_encryption_key` / same |
| delete | `delete_encryption_key` | `fingerprint` | `encryption_key` / `delete_encryption_key` / same |
| enable | `enable_volume_encryption_keys` | `volume_id`, `fingerprints:[one]` | `volume_encryption_key_association` / `enable_volume_encryption_keys` / same |
| disable | `disable_volume_encryption_keys` | `volume_id`, `fingerprints:[one]` | `volume_encryption_key_association` / `disable_volume_encryption_keys` / same |
| passphrase | `update_escrow_passphrase` | `passphrase`, optional `username` | `edge` / `update_escrow_passphrase` / same |
| download | `download_encryption_keys` | `recipient_public_key`, `fingerprints:null` | `edge` / legacy `download_encryption_keys` / explicit `download_encryption_keys` |
