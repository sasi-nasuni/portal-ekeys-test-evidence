## Findings

- **F1 (low, error wording only):** Messages encrypted with the newer AEAD/OCB packet (tag 20) are rejected by the DTO with *"passphrase must be an encrypted PGP message"* (422). This rejection is correct: every filer runs GnuPG 2.2.20, which reports tag 20 as `unknown packet` and could not decrypt it. Customers are not affected in normal use: GnuPG 2.5 encrypting to the filer's real public key (generated by 2.2.20, no AEAD feature) produces a standard SEIPD v1 packet that Portal accepts (`is_encrypted_pgp_message: True`). AEAD only appears when encrypting to a key that advertises AEAD (e.g. a GnuPG 2.5 key), i.e. the wrong recipient; then the caller gets 422 instead of the clearer 400 "not encrypted to the appliance's public key". Optional improvement: name the unsupported packet format in the error. Evidence: `database/aead_gnupg25_passphrase_rejected.asc.txt`, seq 078/079/082/083.
- **F2 (observation):** For `POST /edges/{id}/escrow-passphrase`, the readiness/version gate (405) is evaluated before the recipient check (400) — seq 085 vs 098. Consistent with other writes; noted for API docs.
- No product defects were found in the refactored routes, services, repos, task processing, or watchdog paths exercised.

## Limitations

- Content-endpoint bytes via Swagger: Playwright returns an empty body for Swagger-fetched `attachment` responses; HTTP status/headers were verified natively, bytes were verified by direct HTTP.
- The 409 download conflict, and the bundle decrypt, used direct HTTP (labeled). The first escrow task's evidence was gathered post-hoc.
- `GET /tasks` was checked for shape only; no exhaustive task-list filter matrix.
- Backup-key upload (`backup_key=true`) was not exercised on the real filer (POC already has a backup key; replacement is rejected by design). Only the POC filer was written to.
- Filer log tails are dominated by periodic `List*` refresh commands; per-task command windows (`*_command_window.log`) filter those out for readability; raw tails are kept alongside.
