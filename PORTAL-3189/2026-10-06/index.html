Method and limits

  • Endpoint requests are issued through the served Swagger UI Try it out / Execute controls; returned responses come from the real local Portal server.
  • Swagger uses a single-line input for public_key. Recorded interceptor use preserves multiline armor; explicit invalid-input cases may modify the outgoing parameter after browser validation. Transport notes on each case describe this.
  • Authorization is supplied through local browser request routing. Keys and authorization are omitted from this gallery; masked screenshot regions contain request input or cURL/URL details.
  • An HTTP response screenshot alone does not prove command execution on the filer. Edge Console and filer evidence are reported separately below.
  • UI LIMITATION means browser validation prevented an HTTP request. Such a row is not a verified backend response.
  • The live dev filer reports version 10.5. A user-approved temporary local minimum of 10.5 permits the live dispatch exercise; it does not establish compatibility with the unmodified 10.6 version gate. Check the restoration evidence below for cleanup status.
  • Fixture-based cases verify Portal behavior for the recorded setup. They do not imply that those states were observed on the physical filer.
  • FIXTURE ERROR marks the initial synthetic role setup that omitted an ORM-only default. Those attempts failed before the endpoint; their evidence is preserved, and corrected reruns are listed separately. These are not endpoint test failures.
  • No separate artificial server-failure injection was performed for HTTP 500. The initial fixture error did exercise the generic 500 response. Dedicated download status/artifact routes belong to PORTAL-3190 and are absent on this branch.
